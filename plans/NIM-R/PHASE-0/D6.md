## Description

Define behavior when multiple hooks or clients attempt concurrent submissions.

## Options to evaluate

1. **Single active review only**: concurrent submit produces deterministic collision behavior (409)
2. **Queueing allowed**: ordering, persistence, cancellation, and verdict routing must be specified
3. **Replacement allowed**: overwrite semantics must be explicit and tested

## Required assertions

- First hook not overwritten
- First hook still receives verdict
- Second hook's plan not persisted as active
- Current contract: "single active request; later hooks get protocol-level deny with exit 0"

## Acceptance criteria

- Contract explicitly states which concurrency model
- Contract specifies behavior for all required assertions
- E2E specs reference this contract explicitly
- Implementation matches contract
