## Description

Define and freeze the verdict delivery contract. Are verdicts addressed to a request ID and broadcast to all waiters subscribed to that request, or are they global daemon state?

## Options to evaluate

1. **FIFO consumption**: exactly one waiter receives the verdict; later waiters see idle/no verdict
2. **Broadcast**: all active waiters receive the same verdict; later waiters get either buffered verdict or exit idle
3. **Persistent until clear**: verdict persists in state until explicitly cleared; repeated waits return same verdict

## Required tests to pin down

- Two waiters blocked before approval: both receive same verdict (if broadcast)
- Original submitter plus one explicit waiter: both receive same verdict (if broadcast)
- Waiter started after verdict resolution: receives buffered verdict OR exits idle (contract must specify)
- After all eligible waiters receive verdict: state becomes idle
- Later unrelated wait: does NOT receive stale verdict

## Acceptance criteria

- Contract explicitly states which option (1, 2, or 3)
- Contract specifies behavior for all five required test cases above
- E2E specs reference this contract explicitly
- Implementation matches contract
