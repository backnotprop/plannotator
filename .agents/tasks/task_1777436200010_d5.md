## Description

Define signal handling behavior for CLI and daemon.

## Cases to define

- CLI waiting receives `SIGINT` → exit 130
- Daemon state after submitter `SIGINT`
- Hook shim receives interrupted stdin / broken pipe
- Daemon receives `SIGTERM` during active request

## Options to evaluate

1. **SIGINT cancels active wait only**: daemon remains alive, state unchanged or explicitly cancelled
2. **SIGINT shuts down daemon**: all clients receive specified failure behavior
3. **SIGTERM is daemon shutdown**: crash/recovery tests must distinguish graceful shutdown from crash

## Acceptance criteria

- Contract explicitly states behavior for all four signal cases
- Contract distinguishes graceful shutdown from crash
- E2E specs reference this contract explicitly
- Implementation matches contract
