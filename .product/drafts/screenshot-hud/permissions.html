Behaviour

  • Ask only when needed. Screen Recording on the first capture; Accessibility only when App shots are turned on. Nothing is asked at install or launch.
  • One button. First click: the system request (CGRequestScreenCaptureAccess / AXIsProcessTrustedWithOptions), which registers the app and shows macOS's alert. Later clicks: the deep link (x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture / ?Privacy_Accessibility).
  • Live. While a card is up the app checks every second (a SCShareableContent listing; AXIsProcessTrusted). On success it shows the check and carries on with what the user asked for.
  • Reopen. Offered only when the switch is on (preflight true) but capture still fails, after the user leaves System Settings. Relaunch through LaunchServices; the pending shot resumes.
  • Revoked. A refused capture shows frame 8. The menu-bar item lists both permissions with the same Turn On.

What the live test showed (dev build, ad-hoc signed, macOS 26.3)

  • The prompt appeared, but Plannotator Shots was not in the list: macOS does not list ad-hoc-signed apps. The owner had to add it with +.
  • macOS required Quit & Reopen after the switch (frame 4).
  • A second prompt appeared at the first capture: the private-window-picker bypass confirmation (frame 5).
  • Therefore release builds must be Developer ID signed and notarized. Then the app is listed after the prompt, so frames 1–3 are true. TCC keys the grant to the team id plus the bundle id, so it survives updates (ad-hoc grants reset on every rebuild). MDM can also pre-approve it (PPPC). The CI steps exist and are gated on the Apple secrets.
  • Icon: a neutral placeholder until the owner supplies the app icon (Resources/AppIcon.icns) and the menu-bar template image (Resources/MenuBarIcon.png). The card shows whatever icon the app has, so its picture always matches the row in System Settings.
