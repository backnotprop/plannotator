## Inbox: replies and thread actions

**Reply drafts and the Draft label** (approval "inbox-reply-drafts", variant Label, 2026-10-20; record in `.product/approved/inbox-reply-drafts/`, not in this repo). The owner: "I need a way of knowing that I typed a message and haven't sent... 'not sent' is helpful but 1. looks bad. 2. doesn't help me when I'm no longer in the thread".
- **The words are kept per thread as a server draft** (`packages/shared/inbox/reply-drafts.ts`, `inbox/reply-drafts/<thread id>.json`, 0600 in a 0700 folder, written whole; the store reads them at open, `InboxStore.replyDraft` / `saveReplyDraft` / `deleteReplyDraft`). Outside the event log, like compose drafts: no line, no seq, nothing an agent, the MCP, search or the phone's event stream sees. A save is a compare-and-set on `updated_at` (`base`; `409 draft_conflict` with the newer draft); an empty body deletes it; a deleted thread or project takes its drafts with it. Routes (`packages/server/inbox-reply-drafts.ts`): `GET /api/inbox/threads/:id/draft`, `POST` the same `{ body, base }`, `POST …/draft/delete`; same-origin and `serverSession` for the POSTs, another site's read refused. The reply route's `clear_draft: "<updated_at>"` (the window puts it on the reply that carries the words, naming the `updated_at` they were saved as) deletes the draft with the Send only while it is still that draft (`InboxStore.clearSentReplyDraft`, a compare-and-set: another window's newer draft stays); a Send without it (the phone's) leaves it. A save may name `base_body`, the words that window saved last: a draft still holding them is accepted as the window's own even when `base` is a step behind (the page's last save as it goes). A change sends `event: drafts` `{ thread_id }` on every window's stream (windows only, and `InboxStore.onReplyDraftChange` in-process, which search uses to drop the thread's cached facts so its status filter follows), and the window reads the list and the Drafts again, and the open thread its own draft. A row's comment count is kept per thread as annotations change (`unsentAnnotations`), never scanned.
- **The window** (`packages/inbox/replyDraft.ts`, `useReplyDraft`; `components/DraftLabel.tsx`): typing saves after a 500 ms pause (`REPLY_DRAFT_SAVE_MS`), leaving the thread saves what waits at once, and a page going away sends it with `keepalive` (`pagehide`). Opening the thread puts the words back in the box, open but without focus (j/k and the page keep working). Cancel and Escape keep the words; Discard (the link beside "Saved 4:43 PM" above the box) drops them; the Send that carries them clears them. Each save uses the `updated_at` this window last knew for that thread (kept per thread, also for the save made on leaving a thread). When `event: drafts` says the thread's draft changed (another window, or a Send from the phone), the window reads it (`reload` with the box's words): unchanged since its base, nothing moves; changed, and the box has no edits since its last save or read (or is closed), the window takes the new draft and the box shows its words, or closes when the draft is gone ("This reply changed / was sent or discarded in another window", said in the thread's live region); changed while the box HAS edits, the base does not move, so the window's save (made at once) is refused. A refused save (`409 draft_conflict`) is never written over: the window adopts the draft as the server holds it. When both windows hold words (this box is not empty and differs from the server's), its words stay in the box, not saved, and one line above the box says "Not saved: this reply changed in another window." (or "…was sent or discarded…"), with **Keep mine** (saved over it) and **Discard mine** (only this window's words go: the box takes the other window's words, or empties); the line is not a live region but is said once in the thread's live region when it appears, the textarea names it in `aria-describedby`, focus goes back to the textarea after either button, and the two buttons stay on one line 20 px apart (24 px on a phone), wider than their hit areas reach. An empty box (a delete) or the same words refused shows nothing and never deletes the other window's draft. A Send claims the thread when it starts (`claim`): what waits is saved, every save in flight is answered, the thread's generation is raised (a save queued earlier does nothing) and no save of it runs until the Send ends (`sent`) or fails (`release`); the box is read-only meanwhile (`readOnly`, and its changes are ignored). A Send that fails without a clear refusal (no answer, or a 5xx) after the reply carrying the words went out is read back: the thread is read for a reply with that idempotency key. Found, it went: the Send is finished as if its answer had come (the box closes, the files it carried leave it, the draft is done with, "Your reply went." in the live region). Not there: the words are saved again and the next Send is an ordinary new Send. Not known (the read failed too, e.g. the Inbox is down): the draft stays as it is on the server, the box keeps the words, and the key, the words and what the Send carried (uploads, comments, picks) are kept for that thread (`unconfirmed`). It holds only while the box keeps exactly those words: it is forgotten when any thread read shows the reply landed (and, the box still holding those words, the Send is finished then: the box closes, "Your reply went."), when the words change or the box empties, when the person leaves the thread, and after 10 minutes. The next Send of those words first reads the thread for that key: found, the words' Send is finished and nothing goes again, and anything added since (a comment, a pick, a file it did not carry) stays and is named ("Your reply went. Not sent yet: 1 pick. Press Send to send it."), for an ordinary Send; not there, an ordinary new Send; still unreadable, nothing is sent; the thread deleted (404), "This thread was deleted, so nothing was sent." When the words change or empty, or the box closes, while such a Send is remembered, the thread is read for it and the line says where it is ("Your earlier reply went; Send sends your edited words as another reply.", or "may have gone"; a closed box's draft copy is read again, so no stale "Draft · Your reply" foot stays), and the draft this window's own Send may have cleared is expected (`expectOwnClear`): a save refused for that reason saves the edited words as the new draft, never a conflict line about "another window". Nothing is ever replayed from memory: a later Send always carries what is in the box and the thread now, to the message it answers now. Words a conflict left unsaved are kept per thread at module level (`conflictWords`), so closing or switching the thread never loses them: they come back in the box, with the line, when it reopens. The Send names the draft its words were saved as in `clear_draft` (none after a conflict, so the other window's draft stays and the foot shows it after the Send). The foot's Send (box closed) reads the draft again and carries it as it is now. The page's save as it goes sends `base_body`, and none while a Send holds the thread or after a conflict. The restart guard (`unsentReply`, `unsent.ts`) and a `beforeunload` question ask while files pasted into the box, a save on its way, or a conflict's words would be lost (`replyDraftUnsaved`); a restart the person already confirmed is not asked again. The `beforeunload` listener is registered only while something would be lost (a page with one runs it before every navigation, and some browsers keep it out of the back/forward cache). Files pasted into the reply box are not kept in the draft (pending uploads).
- **"Draft" replaces "Not sent" everywhere**: the question card's tag "Draft" and footer "Picked 4:35 PM · in your draft"; the folded line's "1 pick in your draft"; the thread's foot "Draft · 2 picks" (or "Draft · Your reply, 1 comment") before Send and Edit draft (the foot's Send carries kept words too); above the open box a soft "Draft" pill, whom it goes to (cut with "…"), "Saved 4:43 PM" and Discard (a 44 px hit area on a phone). A replaced question's pick keeps "Not sent": it is never sent, not a draft.
- **The list row** carries the additive `unsent: { reply_at, picks, comments } | null` (`InboxRowUnsent`, `inboxHasUnsent` in `@plannotator/core/inbox-types`): the count slot reads "Draft · Your reply" / "Draft · 2 picks" / "Draft · Your reply, 1 comment" ("Draft" in the accent colour, the rest muted; real spaces, so a screen reader reads words) on wide, two-line and phone rows; an older Inbox's row keeps "Answered, not sent". The section rule is the list's rule 9 above. Mark read on a thread holding words or comments keeps it in New, and its toast says "Your draft keeps it in New".
- **Drafts**: the sidebar's Drafts row counts message drafts plus open threads holding unsent work; `GET /api/inbox/drafts` adds `replies` (those rows, each with `reply_preview`, the words' first 160 characters), and the Drafts page lists them under "Replies not sent" above the messages; a row opens its thread.
- **Phones**: the row's `unsent` rides the list; the door reads a draft (`GET threads/:id/draft`, contract 7.62) and writes none in v1 (the phone composes its own reply).
- Tests: `packages/shared/inbox/store.test.ts` (the thread-state model draws `draft` ops and checks rule 9 and invariant 9 after every step; `adr/implementation/inbox-thread-state.md`), `packages/server/inbox-reply-drafts.test.ts` (routes, guards, conflict, restart, the agent never sees it, `event: drafts`, the compare-and-set clear, `base_body`, the agent's section, search's status filter), the 7.62 case in `inbox-devices.test.ts`, the DOM test `packages/inbox/replyDrafts.test.tsx` (including a Send pressed before the save whose answer is 800 ms late: the draft never comes back; typing during a Send held 1.5 s: the box is read-only and no draft comes back; a failed Send saving the words again; another window sending the words, then this window's refused save adopting the server state with Keep mine; `event: drafts` emitted as the stream does: sent elsewhere closes a box with no edits and refuses one with edits (the conflict, its live-region line and aria-describedby, the restart guard), another window's words replace a box with no edits and stay on the server against one with edits (Discard drops only mine, focus back to the box); an empty box refused shows nothing; a Send after a conflict leaving the other window's draft showing; a Send whose answer is lost after it went read back and closed, comments included; the same words sent later to a new question going to it; a comment made after a Send the Inbox never got riding the next Send; a Send that landed while the thread could not be read found by the next Send, nothing sent again; the foot's Send carrying another window's newer words; an `event: drafts` refreshing the open thread's copy), and `tests/e2e/inbox-reply-drafts.spec.ts` on the compiled binary (type, leave, come back, reload, restart; a picks-only thread stays out of Quiet; desktop, beside a thread, phone, dark).

**Mark read and the Send that skips** (design record "inbox-mark-read", not in this repo; approved 2026-10-11, with the owner's later rulings that Mark read closes the questions it leaves and that Sent sits below New). Two ways to get a thread out of the top without answering every question.
- **A Send skips a question only when the person presses a Skip** (owner approval "inbox-explicit-skip", 2026-10-21, design brief "explicit-skip", option A "never skip on its own"; it replaces the rule of 2026-10-11 that every Send skips what it leaves unanswered, and the 2026-10-13 amendment that skipped once a Send answered one question: on 2026-10-21 the owner answered 1 of 11 questions in one session's 8 messages, and that rule skipped the other 10 in 8 replies). Sending an answer never skips anything else. The reply box (and the foot while picks or annotations wait) shows the chip "N questions stay open · Skip them", always, whatever the Send carries; "Skip them" (or "Skip it") turns it into "↷ N questions will be skipped · Keep open" for that one Send, and is the only way a Send skips. The window remembers exactly the questions the chip counted when it was pressed (`skipArmed` in `Thread.tsx`, ids `<message id>/<key>`), so a question that lands while the person types is never skipped; at Send it passes them to `sendTargetsOf`, which keeps those still open (a pick saved meanwhile is sent as the pick), and the reply names them in `skip` (see "Questions and Send" for one reply per session). Keep open, the thread changing, or the Send going clears the choice. Skip on a card, Mark read and Re-ask work as before. The server takes only the explicit list: `skip: [key | { message_id?, key }]` (`InboxReplyInput.skip`, checked by `planSkips` in the store: a list, each entry a question of a message `sendMessageOf` accepts, else `422 validation_error` / `404 question_not_found`, nothing written; a listed question that is no longer open, answered, picked, closed or replaced, is left alone so a race never refuses a Send). The old `skip_unanswered` flag is ignored by the reply route and gone from the store (the iPhone app never shipped it; contract 7.11 is rewritten): an older client that sends it skips nothing. A skip-only Send whose listed questions all closed meanwhile answers `{ reply: null, nothing_to_send: true }`, a no-op, so the rest of a Send to several sessions still goes. Each skip is a sent skip, `answer: { skipped: true, by_reply: true }` (`inboxSkipAnswer`; `by_reply` is additive on `QuestionAnswer`, kept by `parseQuestionAnswer` only beside `skipped`), so the card says "Skipped · <time>"; the reply's first line counts it ("Skipped 3 questions.", "Answered 1 question, skipped 2."), and each reads "Skipped by the person" in the answers section (a skip is always the person's choice now, so the old "not answered in this reply; treat them as skipped" sentence is gone; a Skip on the card still reads "Skipped"). read_thread's one-line answers say "skipped by the person". Core's `inboxDefaultSkip` (the list row's delivery reads it for which session asked) now always answers false. A Stopped question a Send skipped no longer blocks: the agent has its answer; an unskipped one stays open, so the agent stays stopped and the row stays in Stopped on you or Holding up work (Skip on the card, Skip them, or Mark read free it without deciding). A note on a card (with Skip, or alone) is a pick like any other and goes with the Send as `Skipped` / `Note: …`; each saved pick also updates the pane's `threadRef` at once, so a Send pressed while a note is still saving sends its saved revision instead of a stale one (`question_revision_conflict`) or leaving the note out (`packages/inbox/skipNote.test.tsx`). Tests: `packages/shared/inbox/store-explicit-skip.test.ts` (the owner's case: 11 questions in 8 messages, 1 answered, one reply, 10 open and the line says 10; answers on 3 messages as one reply; Skip them across messages; a question that lands after the press; another session's or thread's message refused; a stale revision on one message refuses all; a replay; a reopen), `packages/shared/inbox/store-mark-read.test.ts` (the skip list, `skip_unanswered` ignored, refusals), `packages/server/inbox-mark-read.test.ts` (the route), the door's 7.11 in `packages/server/inbox-devices.test.ts`, `packages/inbox/sendTargets.test.ts`, the DOM tests `packages/inbox/markRead.test.tsx`, `wordsOnlyTwoAsks.test.tsx` (one reply with answers on both messages; Skip them for the other one) and `skipNote.test.tsx`, and `tests/e2e/inbox-mark-read.spec.ts`.
- **Mark read** (`POST /api/inbox/threads/:id/read`; Undo `…/unread`). Offered where something waits on the person (Stopped, Holding, Waiting, or New with news or picks; `canToggleRead`, `packages/inbox/markRead.ts`) and never on an archived thread (`409 thread_resolved`). The store (`markRead`) writes the root with `person_read_seq` (the seq of that line) and `person_read_at`, counts it as a look, and closes every question still waiting on the person (open, or picked and not sent): each gets a skip answer and `set_aside: { at, read_seq, previous }` (`InboxQuestionRecord`, additive; `read_seq` is that Mark read's `person_read_seq`), so it reads `state: "closed"` with `set_aside_at` on the wire, and refuses a pick (`409 question_set_aside`). The row is Quiet ("Read") while no message but its set-aside note came after the Mark read (`readAt`, derived: an agent's next message, or the person's own reply, ends it with no write; the closed questions stay closed). Undo reopens only the questions that Mark read closed (owner ruling 2026-10-12), exactly as they were, a saved pick included (revision + 1), and clears the root's fields; a question an earlier Mark read closed (and told the agent about) stays closed, so Mark read again then Undo no longer reopens it. A record older than `read_seq` is matched by `set_aside.at` = the root's `person_read_at`. With no Mark read on the root (after an Undo, or an Unarchive that dropped it) Undo writes nothing. On a thread that came back from the archive, a Mark read made after the agent's latest message sends it back to Archived at once, even while the person's earlier reply there waits on the agent (`back_from_archive` reads past that reply while the Mark read stands); a reply the person sends after it brings the thread back as Sent.
- **The agent is told once.** After the Undo window (`INBOX_SET_ASIDE_DELAY_MS`, 10 s: the 7 s toast with 3 s to spare; the server option `setAsideDelayMs`), while the questions are still closed, the server writes one person note per asking message (`tellSetAside`): a reply to that message, `set_aside: [<question ids>]` on it, body "Set aside for now; don't wait on these:" (`INBOX_SET_ASIDE_HEADING`) and the questions as `- Q<n>. <prompt>` (`composeInboxSetAsideBody`). It reaches the agent like any reply (the wake, `wait_for_reply`, `read_thread`), never pushes to a phone (`pushFor` pushes agent messages only), and never ends the read. It is not the person's reply and not a look: the row's `sent`, `unseen`, `waiting_on_person` and "came back", the window's look boundary (`lookBoundary` in `@plannotator/core/inbox-folding`), its "Saved for / Delivered to" line and the held list's agent activity (the row's additive `last_agent_at`) all read past it, so news the agent wrote inside the Undo window stays New after the note goes. Each question is named once, across Mark reads; an Undo inside the window tells nothing. An Undo after the note went sends one more person note per asking message, for the questions that Undo reopened only, "The person reopened these:" (`INBOX_REOPENED_HEADING`, `composeInboxReopenedBody`, `reopened: [<question ids>]` on it), so the agent does not go on believing it need not wait; a later Mark read may then tell it again. A timer per Mark read, one on Unarchive (an archive holds the note back), and a sweep at start (`setAsideDue`) for a note a stop interrupted.
- **The window.** The thread header (owner, 2026-10-16: Archive beside the close, Mark read furthest from it): **Mark read** leads (after `‹ Inbox` and its divider when that shows), with its `E` key; pressed it reads **Read** (`aria-pressed`) and moves it back; disabled ("Nothing here waits on you") in Sent or Quiet. Everything at the right is an icon with a component tooltip (approval "inbox-thread-artifacts", 2026-10-23): **Artifacts** with its count (only on a thread with artifacts, see "A thread's Artifacts"), Expand all / Fold all (`data-expand-all`, named "Expand all messages" / "Fold the earlier messages"; none on a one-message thread or over the Artifacts grid), the Archive icon, a hairline (`ib-vsep`), then the thread's ×; Archive ends the header where no × shows (stacked, a file beside the thread, a phone); the tab order follows (`tests/e2e/inbox-thread-header.spec.ts`). Under the subject while read: "Read 3:14 PM. It stays out of the top until <agent> writes again." and how many questions it closed, with **Move back**. The list row's hover action (and keyboard focus, `:focus-visible`) shows **Mark read** on rows that wait on the person, without opening the thread. `E` marks the open thread (or the row with keyboard focus) and again moves it back; `Z` undoes while the toast is up; neither runs while typing or with a modifier, inside the open file's viewer (`.ib-view`, its stepping guard row) or with a file open unless aimed at the thread or the list, in a guided review, or while the sound dialog is up. The toast (`components/Toast.tsx`, 7 s, `MARK_READ_UNDO_MS`; design record "inbox-toast", approved 2026-10-14): a 40 px line at most 520 px wide (with `--ib-soft-float` a pill on the popover's colour with Soft's floating shadow, its border kept transparent; same size and place) in the look of plan and code review's Sonner toasts (card, 1 px border, 8 px radius, 13 px): an icon, a bold lead, a muted detail, Undo as a filled button with a `Z` hint, and a × at its end. **Closing it early** (owner, 2026-10-20, amending the design's "no close": "a way to grab toasts to swipe remove them or way to clear a toast manually"): the × (`data-toast-dismiss`, named "Dismiss", after Undo / Reply / Open; 24 px drawn, muted until hovered, the Soft hover and pill radius; on a phone a 44 px target from its `::after`; Undo and the × are 8 px apart and their targets meet in the middle of the gap without overlapping, so a tap just past the Undo pill is still Undo) or a swipe: a horizontal drag (touch, pen or mouse; pointer events in `useSwipeAway`, `Toast.tsx`) moves the toast with the pointer through the CSS `translate` property (it composes with the desktop toast's centering `transform`) and fades it; let go past 40% of its width (`SWIPE_DISMISS_SHARE`), or flick it (0.5 px/ms over the last 100 ms, at least 16 px), and it slides out that way (180 ms, played on an inert, `aria-hidden` copy, `data-toast-ghost`, so the window drops the toast at once); short of that it springs back (260 ms, a slight overshoot). While a drag is in progress the 7 s timer is paused (`onHold`, `holdToast` in `App.tsx`) and a spring-back resumes it with what was left (at least 1.5 s); once a drag starts the entrance animation is turned off inline, so a spring-back never replays it. A drag that starts vertical is the page's (`touch-action: pan-y`), one that starts on a button is the button's, and a cancelled one (the browser took a scroll) springs back. Under `prefers-reduced-motion` the toast still follows the pointer but nothing slides: it goes, or snaps back. No library: plain pointer events and WAAPI. Closing it, either way, is `dismissToast` in `App.tsx`: the 7 s timer is cancelled and the toast's Undo goes with it, so `Z` no longer undoes once it is closed, and closing never performs the undo. When a toast leaves by any route (the ×, a swipe, Undo, its timer, a new toast) with focus inside it (a person Tabbed onto Undo or the ×), focus goes back to the element it came from (the `focusin`'s `relatedTarget`), else to the open pane's visible header (the thread's `‹ Inbox`, else its subject), else the page's `.ib-main h1` (or `main.ib-main`), never the body; each is tried until one actually takes focus (on a phone the list's heading is hidden while a thread is open). No key closes it (Escape belongs to the thread), and the live region says nothing about a close. The ×'s room comes from the toast's edges and gaps (`ib-toast-closable`: on a desktop 4 px less padding at its end and none before the actions, and where the words would still take a second line, Undo's `Z` hint is not drawn and the gaps close by 2 px (`data-tight`, decided before paint and on each resize by `useRoomForClose` in `Toast.tsx`; `Z` still undoes and Undo still names its key), which frees more than the × takes (a toast with no Undo has no hint to give up, so its copy keeps room for the ×); on a phone 8 px gaps, 12 px at its start and 9 px inside Undo), so a toast that fit one line without it still does, on a desktop at 520 px and on a phone down to an iPhone SE (`tests/e2e/inbox-mark-read.spec.ts` measures the widest desktop copies both ways). Its words always show whole (owner, 2026-10-18): nothing in a toast is cut with "…"; a lead and detail that do not fit one line wrap to a second (the toast grows from 40 px; the actions keep their line), so copy is kept short enough for one line at 520 px with Undo, `Z` and the ×. "Marked read · Moves to Quiet" from inside a thread (the list holds still until it closes; "Marked read · Goes back to Archived" for a thread that came back from the archive), "Moved to Quiet · “<subject>”" / "Back in Archived · “<subject>”" from the row's hover action with no thread open, and "Marked read · “<subject>”" (phone "Read · “<subject>”") for a row that is not the open thread while one is open (`markReadToast`'s `place`: `open`, `held`, `list`), so it never reads as the open thread; a thread an agent was stopped or held up on gets the warning icon, "Marked read · <agent> was stopped" / "Marked read · Held up N things", and **Reply** (moves it back and opens the reply box). Archive: "Archived" with Undo; Settings' Unarchive: "Back in your Inbox · “<subject>”"; the sound: "Sound off" / "Sound setting not saved" (4.2 s); a failed write: its message, which may wrap. Placement (desktop): always centered on the window, never on a pane (owner, 2026-10-15), 16 px from the window's bottom edge, at most 520 px wide and 16 px from each side, whatever is open (owner, 2026-10-18: a toast is brief, so covering Reply, the reply box or a file's stepping strip for a moment is fine; it no longer measures a pane's or a file's foot and never waits for a loading pane). It is CSS alone (`position: fixed` in `inbox.css`, z-index 41, above a full-screen file's 40); nothing in `Toast.tsx` measures the page on a desktop. A phone keeps its own placement (below). **👍 Looks good** (approval "inbox-acknowledge", 2026-10-15, amended 2026-10-16; not in this repo). "Cool, looks good": the thread goes to Quiet, and after the Undo window the 👍 is sent to the agent that wrote the message as one short turn. The amendment, the owner verbatim: "I replied with looks good, but I realized that doesn't send through. I think we just need to send looks good through, honestly." Before it the 👍 was silent (agents saw it only on their next read).
- The thread's foot is `[↩ Reply] [👍 Looks good]` side by side (44 px each on a phone); 👍 is hidden while any question in the thread is open or picked (and while picks or annotations wait to be sent), once the person wrote back (the last message, the Inbox's notes read past, is theirs), on an archived thread, and with no agent message. No new key; the toast's `Z` undoes.
- `POST /api/inbox/messages/:id/ack` (`{ serverSession?, ack? }`, `ack: false` takes it back; the window's same-origin and `serverSession` guards) → `InboxStore.ackMessage`: an additive `ack: { label: "Looks good", at, read_seq, made_read, settled_seq, settled_at, seen_at }` snapshot line on the agent's message, plus Mark read (`read_seq` = the Mark read it stands on, `made_read` = the 👍 made it). **Replaced questions** (design record, not in this repo; direction A "Quiet"; model agreed with Workspaces).
- An agent supersedes an earlier question of the SAME thread: `supersedes: ["<message id>"]` (every open question of that message) or `["<message id>/<key>"]` on `send_message` (and `submit_guide`, through `SEND_ROUTING_FIELDS`), or a `Replaces: <message id>/<key>` line in a newer block. Core's parser reads that line (`ParsedQuestion.replaces`) only when EVERY token of its value is id-shaped (`msg_` + a 26-character ULID, optionally `/q-` + 8 hex, or a bare `q-` + 8 hex key; one trailing `.` per token dropped), wherever it sits: it is then never the prompt and never context, and it does not change the key. Any other `Replaces:` line is prose (`Replaces: q-learning with PPO`, `Replaces: msg_ queue drain`), so plan review never hides a sentence.
- What replaces it (`superseded_by.key`): the block whose `Replaces:` line named it; through the argument, the new message's only question when it asks exactly one, else null. Null reads "No longer applies"; a key reads "Replaced". Both are `state: "superseded"` on the wire.
- Checked before anything is written (`InboxStore.planSupersede`): every id must name an agent message of the thread the new message lands in (`reply_to`'s, or the routed one) and a question there that is open or picked (not sent, not already superseded, not closed).
