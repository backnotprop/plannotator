## Inbox: System

System is a drawing of a project's code, kept current by an agent when main moves (approval "system-inbox"). It shows only while System is on and Code review is on: `systemShown(settings)` in `packages/inbox/system/gate.ts` is the window's one reading, `systemOn()` in `packages/server/inbox.ts` the server's. Off, the window draws nothing of System (Settings keeps only the switch, while Code review is on) and its routes answer `409 system_off`.

### System: the switch

- **Settings → Capabilities → System**, right under Code review, off by default, shown only while Code review is on (screen 1). It writes config.json `inboxSystem` through `POST /api/inbox/settings` `{ system: { on } }`; every window hears it as `event: capabilities`. The settings answer and that frame carry `system: { on }` only while Code review is on, so with Code review off nothing of System reaches the window. The switch is `systemSwitch()` in `packages/server/inbox-system.ts` (`on`: System AND Code review; `wire`; the POST's `check`, which refuses a tailnet guest with `403 local_only` like every capability switch, and `answer`).
- **Its words**: "A drawing of each project's system, kept current by an agent when main moves. Shows while Code review is on. Off, none of it shows; every drawing is kept. Yours alone."
- **On**, the row lists the projects (`GET /api/inbox/system/projects`: every project whose folder is on this Mac with a git `origin`, plus any with a drawing in the data folder), each with its drawing in words (`systemStateWords`, `system/projects.ts`: "Not drawn yet", "7 sheets", "Drawing 2 of 7" in the drawing phase, "Needs a redraw" for a drawing that does not read) and Set up (`openSystemSetup(project id)`) where the folder is here.

### System: Reviews

- **The System button** (`system/SystemButton.tsx`, screens 3 and 2a) sits in the Reviews head beside the filter mark while System shows. Its menu: "System", the projects with a drawing (`systemListed`: drawn, being drawn, or not reading) with their state words, or "No project is drawn yet.", then "Set up a project" (the setup dialog). A pick opens the project's drawing; the list is never filtered by it (Reviews with no filters, variant B). While a drawing is open the button names its project, in the filter's picked fill (`--ib-cur-bg`), never an outline. The projects are read when Reviews opens and again each time the menu opens.
- **The drawing in the pane** (`system/SystemPane.tsx`, screen 4a): the address is `#reviews&system=<project id>` (`&sheet=<code>` for the sheet on screen, kept as the person travels). The pane draws the package's `SystemView` (layout `pane`, `keys={false}`: the drawing's single-key shortcuts stay off, approval "system-navigation") from `GET /api/inbox/system/drawing`, with its close button; Simple / Full is remembered for the window's life. Under it, "Open PRs that change this": `GET /api/inbox/system/pulls` reads the open PRs of the project's repo from the pulls list's own read, each PR's files from its patch (the reader's cached diff), kept by head commit for the Inbox's life (`systemFilesCache`: a PR is read again only when it moved, so reading the pane again with the list costs nothing), and the package's `gate()` names the drawn parts each touches; the drawing marks those parts amber at rest, each tagged with its PRs (SystemView's `touches`, one per PR, labelled "PR <n>" with its gate result: "PR 2850 · PR 2851", past two "PR 2850 +2"), and the rows name them too; a row reads "#12 · title / changes <parts> · <its review thread or why it is on you>" and opens that PR's pane (`&stack=`, which closes back to the drawing as it was, the full window too). PRs whose patch can't be read are counted under the rows. A project not drawn yet (or whose drawing does not read) says so, with Set up.
- **Full window** (screen 4b, `&full=1`): the same drawing over the whole window (layout `window`), the PRs beside it, "‹ Reviews" at the start of the drawing's bar (SystemView's `leading`; a strip of its own only while no drawing shows) to go back. What it covers is `inert` while it is open (`inertAround`), so Tab stays in it. A phone draws the drawing in the list's place, with "Reviews" back and the PRs under it; there the zoom group sits at the top right, since a phone's sheet reaches the bottom left.
- **Escape** backs out one layer (App.tsx, `systemEscapeTo` in `system/route.ts`): the drawing's own first (a card, a sheet inside), then the full window, then the drawing; never under a PR's pane. No new shortcut.
- **Focus**: closing the full window returns it to "Open full window"; closing the drawing, to the System button.
- **Off is today's**: while System does not show, a leftover `&system=` link is dropped in place (`systemDropped`), never carried into a new Reviews address (`systemKept`), and Escape is not System's.
- **Not yet**: the dot for a drawing changed since last opened (staying current, B9) and the drawing phase's live pane (B5). 
- **Tests.** `packages/server/inbox-system.test.ts` (the projects listed, the drawing read only from the data folder, the PRs that touch it and read once per head, the routes' guards, the switch: both halves, the guest refusal, validation, the answer), `packages/inbox/system/route.test.ts` (the address, what a new address keeps, a leftover link dropped, the Escape order), `packages/inbox/system/systemInReviews.test.tsx` (DOM: the switch under Code review, the projects with Set up and read only while System shows, the button and its menu, the pane, its PR rows, the full window, inert behind it, focus back).

### System: project setup

- **Opening it.** `openSystemSetup(projectId?)` (`packages/inbox/system/opener.ts`) from anywhere in the window: the System button's "Set up a project" and Settings' Set up call it. `SystemSetupHost` (`system/SetupHost.tsx`, mounted once in `App.tsx`) draws the dialog only while `systemShown`. `?system-setup` (or `?system-setup=<project id>`) in the window's address opens it once System shows, for tests and pictures.
- **The steps** (`system/SetupDialog.tsx`, one native dialog; a bottom sheet on a phone). 1, Project: every project whose folder is on this Mac with a git `origin`, from `GET /api/inbox/system/setup`; nothing to type. 2, What to read: the project's own repo (from its remote, not removable), extra repos (`owner/name`, `host/owner/name`, an https link into the repo, or an ssh remote) and doc sites (a URL; a bare host gets `https://`). Words typed and not added go in with Next; a field that does not parse says why and holds Next. Enter in a field adds it (the field is a form). 3, Who keeps it current: every agent the Inbox launches itself (Claude Code, Pi, OpenCode; none needs connecting first), each with a model choice (Claude Opus 5.5, tagged Recommended whichever is picked, or the agent's own default). The model is saved in the agent's own form: `claude-opus-5-5` for Claude Code, `anthropic/claude-opus-5-5` (`provider/model`, their `--model`) for Pi and OpenCode (`systemRecommendedModel`); picking another agent carries the recommended model over in that agent's form. That one choice runs the drawing phase and every redraw; nothing asks again. A chosen row takes the thread rows' filled highlight (`--ib-sel`), never a border or outline.
- **The end.** With the picked agent one the Inbox can start here (`GET /api/inbox/sessions` `launch.agents`, mapped by `systemAgentOfLaunch`), Draw it saves and calls `startFirstDrawing` (`system/firstDraw.ts`, a stub until the first draw lands). Otherwise (launch off, or that agent not startable here: the fallback), Copy prompt starts the copy inside the click, saves, and closes with a toast; a failed copy keeps the dialog open (the choices are saved). The prompt is `systemFirstDrawPrompt` (placeholder text until the drawing recipe's `firstDrawPrompt` lands). Cancel saves nothing.
- **`setup.json`.** `<data dir>/system/<project key>/setup.json`, 0600 in a 0700 folder, written whole: `{ v: 1, repos: string[], docs: string[], agent: "claude" | "pi" | "opencode", model: string | null, thread_message: string | null }` (`model` in the agent's own form, see step 3; null: the agent's own default). `repos` are the extra repos only, as `host/owner/name`; `docs` full URLs. The contract and its parsers are `packages/core/inbox-system-setup.ts` (browser-safe: the dialog and the server parse alike); the file is `packages/shared/inbox/system-setup.ts`; the routes call `packages/server/inbox-system-setup.ts`. Bun only (Inbox routes): no Pi twin.
- **Words.** On screen: "the drawing phase", "setup", "redraw"; no engineering terms. A redraw keeps the drawing of today's code current; Shape is a planned change; nothing in System calls a redraw a Shape.
- **Tests.** `packages/core/inbox-system-setup.test.ts` (the parsers and the save's check), `packages/server/inbox-system-setup.test.ts` (setup.json on disk, the projects offered, the route's guards through `systemSetupRoute` with no Inbox started), `packages/shared/inbox/system-setup.test.ts` (the key check, the folder's mode, no temp file left), `packages/inbox/system/setupDialog.test.tsx` (DOM: the steps, validation, Draw it and Copy prompt, nothing with System off).
- **Pictures.** An Inbox started with `PLANNOTATOR_TEST_SANDBOX=1` finds no agent CLI, so it shows the Copy prompt fallback; Draw it shows only with a launchable agent.
