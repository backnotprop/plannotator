## Inbox: Grid (experimental)

Grid is one page of all the agents' work (owner approval "inbox-agent-grid", round 3). It shows this computer's work and the work of every linked computer. The work is grouped Needs you, Moving, Not moving, Stale, Landed, Not started and Dropped. The page starts with a line of plain counts and a "Since" line. Each line shows the work's name and PR number, its agent, a bar of its life on the page's clock, and the bar in words ("Working 2 h › PR 40 min › Needs you 32 min"). An open question sits under the name in amber.

**The switch.** Experimental, off by default: Settings → Capabilities → Experimental → Grid. It is config.json `experimental.grid` and `PLANNOTATOR_EXPERIMENTAL` name `grid` (see `environment.md`). `POST /api/inbox/settings` takes `{ experimental: { grid } }`, alone or with `decision_mode`. While the variable decides, the save answers `409 experimental_env_decides`. When the switch is off, nothing of Grid runs or is written: no sidebar row, no read, no look, no timer. A `#grid` address goes to the Inbox (`GridRoute`). A sidebar save while it is off never writes `grid`: the server leaves it out of config.json `inboxSidebar` (`inboxSidebarOff`, `inbox-sidebar-save.ts`) and the window leaves it out of the cookie (`setSidebarUnsaved`, `sidebarLayout.ts`), as for an off Plans. When it is on, the sidebar's Grid row sits under Inbox (core `inbox-sidebar.ts`, hideable).

**Where the code is.**
- `packages/shared/inbox/grid.ts` holds the rules. It is pure and reads nothing: `gridPlace` puts one thread in its group, and `createGridModel` builds the page (groups, counts, Since, the lines only counted, Earlier and the clock's span), kept between reads. `gridSaid` gives the bar's words, `gridLandedWord` Landed's word, `gridHourTicks` the clock's local hours. Unit tests are in `grid.test.ts`.
- `packages/inbox/grid/gridInput.ts` turns the window's list rows and agents into `GridThreadIn` (pure).
- `gridSeen.ts` sends the looks; `gridOn.ts` holds the switch and the list reads Grid's events ask for.
- `GridPage.tsx` and `GridLine.tsx` draw the page and its lines; `grid.css` styles them. `gridNudge.ts` sends a nudge; `gridMotion.ts` and `grid-motion.css` are the motion.
- Server: `inbox-grid-seen.ts` (the looks), `inbox-grid-row.ts` (what a row carries for Grid), `inbox-grid-nudge.ts` (a row's `grid_nudge`).
- Tests: `gridPage.test.tsx` (DOM), `packages/server/inbox-grid-seen.test.ts`.

**One line per piece of work.** A piece of work is a list row with an agent. A PR put on two threads is the work of the thread it was put on first (then the lower thread id): one line, counted once. A thread with several PRs is one line over all of them: open while any is open; Landed when none is open and one merged (at the last end); Dropped "PR closed" when all closed.

**Off adds nothing.** Grid's fields (`now`, `grid_seen`, `grid_nudge`, `steps_progress`, `pulls.items`) are on a list answer only for a read that asks `grid=1`: the window asks only while Grid is on and its page shows (`listRead.ts` `setListGrid`, from `gridOn.ts`), a linked machine only while Grid is on there (inbox-peer-link.ts `gridOn`). A server with Grid off ignores a window's `grid=1`, strips them from linked rows for a read that did not ask (`gridRowStripped`), shows no `clock_ms`, and sends no `grid-seen` to its windows; its links ask for no `grid-seen`. Turning Grid on or off redials each link quietly (`gridChanged`). Guarded by `packages/server/inbox-grid-off.test.ts`.

**Data. Only what the list already carries; Grid reads nothing of its own.**
- The list is the merged list, so a linked computer's rows, agents (with their `status_mark`), `run`, PRs, checklists and looks come the same way as local ones; the readout names the computer.
- The row's PR summary carries every PR (`pulls.items`: `added_at`, `read_at`, `checks`, `review`), from the store and the thread-PR states the list read already refreshes. A `thread-pulls` event (checks or review changed) reads the list again only while Grid shows, once per burst (`gridHeard`).
- `steps_progress` on a row: the latest checklist's done, counted, the step in progress and its last change, while that computer's Checklist switch is on. A step's change is movement; the readout says "Steps 2 of 5" and the step in progress.
- Clocks: the list answers with its `now`; a linked machine reads how far apart the two clocks run (`clock_ms` on its `machines` entry, whole minutes, absent within two minutes). Grid takes it off every time of that computer's rows, so a clock that is off does not make work look quiet.
- Time marks:
  - The PR piece starts at the first PR's `added_at`.
  - "Merged" and "closed" are at the PR's `read_at` (when the Inbox saw that state). This is close to the real time, not exact.
  - "Needs you" starts at the row's `waiting_since`.
  - A permission prompt in a terminal has no words or time on the wire. Its line says "Asks for permission in its terminal" and starts at the last movement.
- A closed PR is read again at most every 10 minutes for a week after it closed (`inbox-thread-pulls.ts`), so a reopened PR comes back. Merged is never read again.

**Seen.** A line counts as seen only once at least half of it was on screen in a tab that shows (an IntersectionObserver; no layout read). A line behind "N more" or a closed Earlier is not drawn, so not seen; the landed lines only counted in the Since line are seen when that line is. The look is kept with the thread on its own computer: `POST /api/inbox/grid/seen` `{ seen: [{ thread, through, at }] }` (`through`: the line's last landing or drop shown; `at`: when; each keeps its larger value; ahead of the clock is now), in `inbox/grid-seen.json`, kept while this Inbox holds the thread (never dropped for age or count). A linked computer's window sends it through the forward (outbox `set`), a phone through the door; `event: grid-seen` makes windows and linked machines read the list again (a reread event, `PEER_REREAD_EVENTS`). Rows carry it as `grid_seen`. A sitting compares with the looks it found when it began, so bold stays bold while the person reads; a sitting begins when the page opens or the tab shows after 5 minutes away.

**The decay rules** (`gridPlace`):
- Open work stays: Moving, then Not moving after 20 quiet minutes. Not started is a message sent and not yet checked, the agent never having answered.
- Work that needs the person never leaves because of age.
- Landed stays for at least 3 h and until its line is seen. Unseen for more than 12 h it is only a count in the Since line, until that line is seen. Once seen and older than 3 h, it moves to Earlier.
- Nothing else leaves without Dropped: all its PRs closed, its agent ended, or 3 days with no movement. Dropped stays for at least 3 h and until seen, however long; then Earlier.
- Earlier keeps work for 7 days after it was seen (and its 3 h). It is made again from the rows each time.
- An end older than 7 days that no look ever showed happened before Grid could show it: not drawn.

**Cost.** Nothing in a line measures. The bar's pieces are positioned by percentage, and the readout is a CSS `:hover` / `:focus-within` child (on a phone, a tap opens it, with Open thread). Its rows share one set of columns (CSS subgrid, `max-content`), so the time ("Tue 10:09 AM" or a longer locale's), the state and the detail line up and never overlap: no fixed column width. A thread's place is worked out again only when what Grid reads of it changed (compared field by field, `gridSameIn`; no JSON) or the clock reached its next mark (`gridPlaceTimed`'s `until`: the next minute for a bar that runs to now, else 3 h, 12 h, 3 days or a week); otherwise its line keeps its object, so its memoized drawing holds. A list read is O(n) to compare plus the changed threads to place, and O(n log n) to sort; the minute tick places again only the open lines.

**Screen readers.** A line's name says its group and its bar in words ("Pagination cursors. Needs you. Working 1.5 hours, Needs you 32 minutes. Keep the old page param?"); the readout, with the times, describes it. The bar is hidden from them.

**Stale (round 4).** A group between Not moving and Landed. Its line has a long brown-grey tail and reads "Stale 3 h". Work is stale when it started, nothing happened for 3 h (`GRID_STALE_MS`) and its agent is still there; or when a plan was made 12 h ago (`GRID_PLAN_STALE_MS`) and nothing started ("Planned 7:20 PM › Stale 14 h · not started"). Work that waits on the person is never stale. Any movement (a push, a step, a check run, a message) puts it back in Moving. It is worked out from what the rows already carry: agents do nothing new. Tests: `packages/shared/inbox/grid-stale.test.ts` (the 2 h 59 / 3 h and 11 h 59 / 12 h edges, Needs you, the nudge's own delivery not being movement).

**Nudge (round 4).** A stale line offers Nudge: on a desk, a button at the end of the name while the line is pointed at or holds focus; on a phone, in what a tap opens, beside Open thread. One press, no confirmation. It sends the agent a reply from the person in the work's own thread, through the ordinary reply route (`POST /api/inbox/messages/:id/reply`, or `/api/inbox/m/<machine>/…` for a linked computer's thread: through the forward and the outbox, so it is held while that computer is away and written once). The reply carries `nudge: { quiet_from }` (`grid-nudge-mark.ts`; the thread shows "Nudge from Grid" beside its recipient; `agentThread` strips the mark, so the agent reads only the words). Its words (`grid-nudge.ts`): a first sentence from the line (name, quiet length, one detail: tests failing, still a draft, or planned and never started), then always `GRID_NUDGE_ASK`. The idempotency key is the thread, its quiet stretch's start on the thread's own clock, and the 3 h period: a second press, a second window or a held copy writes one nudge. The message it answers is worked out on the thread's computer (`inbox-grid-nudge.ts`: the same default as a typed reply, else the thread's first message) and carried on `grid=1` rows as `grid_nudge: { to, seq, last }` (`seq`: the thread's newest seq there, sent as the reply's `seen_through_seq`, which a reply forwarded to another computer must carry; an agent message since refuses the nudge; `last`: the newest nudge and when its agent first answered after it). A computer without this field offers no Nudge. After a press the line says "Nudged just now" and its readout lists the nudge; Nudge is not offered again for 3 h in that quiet stretch. The nudge's delivery is not movement; an answer is, and the stretch stays on the bar as a past Stale piece. Tests: `packages/server/inbox-grid-nudge.test.ts`, `inbox-grid-nudge-far.test.ts` (two linked Inboxes, held and delivered once; CI), and `gridPage.test.tsx`.

**Motion, Glint (round 4).** `gridMotion.ts` and `grid-motion.css`. Ship's light crosses one Moving bar at a time, walking down the list (a line every 1.7 s, none twice within 7 s); that line's agent mark bobs. Only Moving moves; Not moving, Stale and Dropped stay still. Shared moments: a line that changes group slides there (0.4 to 0.8 s by distance); a line going stale lets its grey go to the stale colour (1.8 s); a merge settles with a soft purple light; Needs you breathes amber on its waiting tip (3.4 s, all in step); a nudge sends a warm light along its bar, then a soft light at its end. The script only sets an attribute on a line; CSS animates transform and opacity. One timer while the tab shows and none while it is hidden; a line off screen (no `data-vis`, from the page's one IntersectionObserver in `gridSeen.ts`) never glints; with `prefers-reduced-motion` nothing moves. The slide reads the place of only the lines that changed group.
